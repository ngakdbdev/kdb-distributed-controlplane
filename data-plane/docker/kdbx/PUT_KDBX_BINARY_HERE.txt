This is the BINARIES FOLDER. Docker mounts it read-only into every kdb service
(at /kdbx) and each container picks the binary for its platform at start - so one
image runs on amd64 or arm64 with no rebuild.

You can add binaries in EITHER form:

  (a) Just drop the KX portal zips here and the container unzips the one it needs
      into a writable cache at start:
          l64.zip       Linux x86-64
          l64arm.zip    Linux ARM64 (Graviton etc.)
          m64.zip       macOS x86-64     (host/agent use, not Linux containers)
          w64.zip       Windows x86-64   (host/agent use, not Linux containers)

  (b) Or pre-unzip them (unzip l64.zip here -> l64/q), or run ../stage-kdbx.sh.

Each portal zip contains ONLY the binary (e.g. l64/q); q.k is embedded, so no
separate q.k is needed. Then add your LICENCE at the top level:

    k4.lic      your KX licence (or kc.lic)

Precedence: a binary/zip here is always used first; the KX-portal pull (needs
KX_INSTALL_SOURCE=kx-portal + KX_BEARER_TOKEN) only runs as a fallback when
nothing is staged here. For the Linux containers you only need l64 (or l64arm on
ARM hosts); the mac/windows builds matter only if you run q/the agent on those.

KDB-X Community Edition is free (no expiry, commercial use allowed):
https://kx.com/products/kdb-x/  - fetch it yourself. This directory is
git-ignored on purpose; NEVER commit a licence file or a binary.
